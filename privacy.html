Scale Local privacy policy

Effective date: 16 October 2026

This policy describes the self-hosted Scale Local Ubuntu application, its optional Google Health API integration, and this public information website. The separate Android application's Health Connect integration has its own in-app privacy disclosure.

1. Self-hosted operation

The installation owner runs Scale Local on their own Ubuntu computer and controls that computer, selected scales, dashboard, backups and Google connection. The project maintainer does not operate a central measurement-collection service and does not automatically receive records, credentials or diagnostic logs from installations.

2. Data processed and stored locally

The application receives Bluetooth advertisements to recognize explicitly selected, supported scales. Saved local records can include:

  • Final weight, Ubuntu receipt timestamp, and the local UTC offset recorded at that time.
  • Scale Bluetooth address and model, signal strength, impedance values, and the raw measurement payload.
  • Local record identifiers, deduplication state, selected scale addresses, sharing preferences, upload state, returned Google resource names, and non-sensitive synchronization errors.

These records support local history, display, CSV export, duplicate handling and the optional upload queue. Temporary settling readings can be displayed but are not saved as final measurements. The application does not identify who is standing on a scale; a shared scale can record other people's weigh-ins.

3. Google identity and authorization

Google sharing is optional and disabled by default. Connecting an account uses Google's OAuth consent flow with:

  • openid to verify the selected Google account's identity and bind queued records to that account/client.
  • https://www.googleapis.com/auth/googlehealth.health_metrics_and_measurements.writeonly to create weight records in Google Health.

The health write permission is not limited to weight at Google's permission boundary: it can add supported health measurements and edit/delete data the application adds. Scale Local implements only weight creation, not cloud record editing/deletion or health-history reading. It does not request email, profile, or health-read scopes.

Signed identity information is verified to obtain an account identifier. A hash binding that identifier and OAuth client is retained locally. The application also processes OAuth client configuration, access tokens and refresh tokens. Access tokens stay in memory; refresh tokens and client configuration are kept in service-user-owned, permission- restricted files on the Ubuntu computer. OAuth callback access logs are suppressed. A Google password is entered only into Google's own sign-in flow, not into Scale Local.

4. What is sent to Google

After authorization and explicit enablement, newly saved final readings from the selected scales are eligible only if their unrounded weight is strictly over 140 lb. The uploaded measurement contains only weight and measurement time, including UTC offset. The timestamp is the Ubuntu receipt time of the saved final measurement.

Bluetooth address, signal strength, raw payload, impedance, body-composition estimates and local record identifiers are not included in the uploaded measurement. Google receives the OAuth authorization needed to process the request and can associate API/application metadata with the record. Google processes submitted data under its own terms and privacy policy.

Older unqueued history is not backfilled. Existing consented queue items may resume when sharing is re-enabled. Potentially completed but unconfirmed requests are held for review to reduce duplicate uploads.

5. Permitted uses and limited use commitment

Google identity and authorization data are used only to provide the requested account connection and weight-upload feature. Locally received measurements are used for the application's visible monitoring, history, export and sharing features.

Scale Local's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

The application does not sell Google user data or measurements, use them for advertising or credit decisions, or send them to AI services for model training. It has no built-in analytics, advertising, or developer telemetry service. The maintainer has no routine access to an installation's Google data. Any separately requested support disclosure must be limited to what the installation owner chooses to share.

6. Access and security

Outbound Google requests use HTTPS. Database and credential files use owner-restricted operating-system permissions. These files are not separately encrypted by the application; the owner is responsible for account security, disk encryption and protected backups.

The default read-only dashboard listens on localhost and has no login. Other users or programs on the same computer may be able to view it. Optional LAN access requires a separately configured HTTPS/password proxy. The owner must not expose the unauthenticated dashboard to the public internet. This website does not proxy or connect to dashboards.

Desktop OAuth clients cannot keep a confidential client secret. Refresh tokens must be treated as sensitive even if a client ID/secret is known. If credentials are compromised, revoke the Google connection and replace affected credentials.

7. Retention, revocation and deletion

Local records have no automatic retention limit and remain until the owner removes them from their local storage. The owner controls exported CSV files and backups; removing an original file does not remove copies. The read-only dashboard does not provide deletion controls.

Pausing sharing stops new queueing and future requests, but an already sent request may finish. Disconnecting attempts to revoke Google authorization before removing local credentials and cancelling pending uploads. If revocation cannot be confirmed, the application reports the failure rather than claiming that Google access was removed.

Google access can also be revoked through Google Account connections. Deleting a local token file is not revocation of a stolen copy. Disconnecting or deleting local history does not delete measurements already held by Google. Use Google Health's available data/privacy controls or Google support to manage those cloud records.

8. This information website

This is a static site hosted by GitHub Pages. It has no sign-in form, measurement API, embedded analytics, third-party fonts, cookies or browser-storage code. It does not receive Google authorization codes, tokens or scale measurements.

The hosting provider can process standard connection/request information when a browser visits the site. See the GitHub General Privacy Statement for its handling of hosting-related data.

9. Contact and policy updates

For software or policy questions, use the project issue tracker. It is public: do not post measurements, Bluetooth addresses, credentials, tokens or personal diagnostic logs. For data retained by a particular installation, contact that installation's owner; the maintainer cannot retrieve or erase records from computers they do not control.

Changes to data handling must be reflected in this policy and the application's disclosures. The effective date above identifies this version. This page describes application behavior and is not a claim that Google has verified or endorsed the project.
